# 케셰브(Keshev) 완성본 시연 및 검증 기록

> 작성 기준: GitHub `main` 브랜치의 소스 및 병합 기록. 작성자가 사용자의 PC에서 직접 실행하거나 스크린샷을 수집한 것은 아닙니다. **구현 확인과 실행 검증을 구분**합니다. 기존 제출물·프로젝트 폴더는 보존하며 앱 포장 명령을 실행하지 않습니다.

## 1. 프로젝트 개요 및 화면 구성

케셰브는 제공된 사용자·기기·세션, 업무 앱 접근 판정, 보안 기록 및 취약점 조회 기능에 학생 구현 화면을 더한 로컬 보안 Agent 프로젝트입니다.

- 화면 전략: **관제 대시보드형**. 상단 상태 카드 4개를 중심으로 상태를 보여 주고 아래에 측정 추이와 최근 기록을 배치하는 구성을 목표로 합니다. 실제 카드 배치 및 표시 내용은 실행 화면에서 확인해야 합니다.
- 실행 방식: **포장 없이 기존 프로젝트 폴더에서 직접 실행**합니다. `npm run package-app`은 실행하지 않으며 포장 스크립트를 만들지 않습니다.
- 데이터 원칙: **실제 측정값**은 단위·측정 시각과 함께 표시하고, **설명용 예시 값(demo)** 은 실제 조회 결과로 해석하지 않습니다. 조회 실패는 `확인 불가`와 이유를 표시해야 하며 0 또는 정상으로 바꾸지 않습니다.

## 2. 제공 기능과 학생 구현 기능 구분

| 구분 | 기능 | 근거 및 주의 |
|---|---|---|
| 제공 | 사용자 로그인·기기·세션 정보 표시 | 기존 제공 UI 및 API를 이용하는 기능. 실제 로그인 성공은 별도 확인 |
| 제공 | 업무 앱 접근 판정 | 제공된 판정/화면 기능. 실서버 정책 적용 여부는 미확인 |
| 제공 | 접속·XDR 보안 기록 | 제공 기록 조회 기능. 표시된 기록이 실데이터인지 demo인지 확인 필요 |
| 제공 | AI 사건 설명 및 조치 요청 상태 | 설명·제안이 곧 조치 집행을 뜻하지 않음 |
| 제공 | 설치 패키지 취약점 조회 | 조회 기능의 실환경 결과는 미확인 |
| 학생 구현 | PC 자원 측정·관제 | `src/pc-status.mjs`, `public/pc-dashboard.mjs` 및 관련 화면 |
| 학생 구현 | CPU 추이 및 최근 측정 기록 | 브라우저 세션에서 실제 조회 결과를 비교하도록 작성됨 |
| 학생 구현 | Windows 상태 읽기 전용 조회 | `src/windows-status.mjs`; 네트워크·방화벽·System/Application 이벤트 통계 |
| 학생 구현 | 핵심 기능 3가지 요약·다시 조회 | `student/extension.mjs`; 제공 API 결과의 상태를 표시 |
| 학생 구현 | 홈페이지 접이식 실행 안내 | `public/index.html` 및 `public/style.css` |

학생 영역의 **기기·세션 보호, 보안 기록, 취약점 점검**은 제공 API의 상태를 요약하는 화면입니다. 이를 학생이 해당 보안 엔진 전체를 직접 구현한 것으로 표현하지 않습니다.

## 3. 핵심 기능 3가지 시연 순서 (약 5~7분)

### ① 기기·세션 보호 (약 1~2분)

1. 로컬 앱의 **보호 현황** 화면을 엽니다.
2. 제공된 현재 로그인·기기·세션 정보 영역을 확인합니다.
3. 학생 영역의 **기기·세션 보호** 요약 상태를 확인하고 **다시 조회**를 누릅니다.
4. 로딩 중, 실제 조회, 예시 자료 또는 확인 불가 중 **실제로 나타난 상태**를 설명합니다.

**성공 판단:** 화면에 조회 결과와 그 상태가 나타나는지 확인. 이것만으로 외부 보안 정책의 실효성을 검증했다고 주장하지 않습니다.

### ② 보안 기록 (약 1~2분)

1. **보안 기록** 메뉴로 이동해 제공 기록 화면을 확인합니다.
2. 학생 영역의 **보안 기록** 상태를 확인합니다.
3. 보호 현황의 **연결과 기록**에서 Windows 상태 조회를 실행하고 조회 시각과 오류 이유를 확인합니다.
4. System/Application 경고·오류 **건수는 운영체제 이벤트 통계이며 침해·공격 탐지 건수가 아님**을 설명합니다.

**성공 판단:** 조회된 값·단위·시각을 제시하거나, 조회 실패 시 `확인 불가`와 오류 이유를 그대로 보여 줍니다.

### ③ 취약점 점검 (약 1~2분)

1. 제공된 업무 앱/취약점 관련 영역을 열어 조회 상태를 확인합니다.
2. 학생 영역의 **취약점 점검** 요약을 확인합니다.
3. **다시 조회** 후 실제 결과인지 demo인지, 또는 실패했는지 구분합니다.

**성공 판단:** 응답 상태를 정확히 표시하는지 확인. 취약점이 없다고 나오거나 조회에 실패한 경우, 실제 환경 전체가 안전하다고 단정하지 않습니다.

### 보조 시연: 로컬 PC 관제 (약 1분)

1. **보호 현황**에서 상단 관제 영역을 확인합니다.
2. CPU(%), 메모리(GB), 디스크 여유(GB)와 측정 시각을 읽습니다.
3. **새로 측정**을 눌러 추이·최근 기록이 어떻게 바뀌는지 확인합니다.
4. **SDP 미연결**은 로컬 PC 측정 성공과 별개라고 설명합니다.
5. 접이식 **실행 안내 한 장**을 펼쳐 실행 방법을 확인합니다.

## 4. 한계와 미확인 사항

| 항목 | 현재 확인 상태 | 제출 시 표현 |
|---|---|---|
| 다른 사용자 PC에서 독립 실행 | 미확인 | 실행 안내는 마련했으나 타인 재현 검증은 남음 |
| 실제 SDP 서버 연결 | 미확인 | 실제 연결 검증 없이는 `SDP 미연결`로 취급 |
| Windows 이벤트·방화벽 조회 | 실제 사용자 PC 결과 미확인 | 권한/환경에 따라 `확인 불가` 가능 |
| 취약점 API 실환경 응답 | 미확인 | 소스의 조회·표시 기능과 실측 성공을 구분 |
| CPU·메모리·디스크 실측 | 소스 구현 확인, 사용자 PC 결과 미확인 | 수치·단위·측정 시각이 담긴 캡처 필요 |
| 전체 UI 및 회귀 테스트 | 사용자 PC 검증 기록 미확보 | 코드 병합이 실행 검증 완료를 뜻하지 않음 |

## 6. 재현 가능한 실행 명령 및 확인 순서

Windows PowerShell 기준입니다. 기존 로컬 수정 사항이 있다면 `git switch`/pull 전에 `git status`를 확인하고, 강제로 덮어쓰지 않습니다.

```powershell
cd C:\Users\user\alekov
git status
git switch main
git pull --ff-only origin main
git rev-parse HEAD
cd .\alekov\on-client
node --version
node --check .\student\extension.mjs
node --check .\public\pc-dashboard.mjs
node --check .\src\server.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

브라우저에서 **http://127.0.0.1:5189/** 에 접속합니다.

**확인 순서:** 실행 안내 펼치기 → 상단 관제 상태 확인 → PC 새로 측정 및 추이·기록 → Windows 상태 조회 → 기기·세션 보호 → 보안 기록 → 취약점 점검 → 각 화면의 실제/예시/확인 불가 구분.

서버 종료는 PowerShell에서 **Ctrl+C**를 누릅니다. **`npm run package-app`을 실행하지 않으며, 새 포장 스크립트도 만들지 않습니다.** 기존 프로젝트 폴더 및 이미 제출한 자료는 이동·삭제하지 않습니다.
