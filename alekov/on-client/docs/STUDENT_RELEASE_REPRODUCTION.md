# 케셰브 — 22단계 새 환경 재현 및 릴리스 기록

> 상태: **검증 중**. 이 문서는 현재 원문을 대조한 재현 절차와 학생 기록 양식입니다. 작성자가 사용자 Windows PC에서 새 폴더로 clone·실행·시연한 결과는 **없으며 모두 미확인**입니다. 실제 확인 후 같은 최종 커밋 기준으로 갱신해야 합니다. 원래 작업 폴더·Git 기록·인증 파일을 변경하거나 삭제하지 않습니다.

**커밋 일치 원칙:** 최종 문서를 수정하면 새 커밋이 생깁니다. 모든 실행 기록은 실제로 테스트한 **동일한 40자리 커밋**을 가리켜야 합니다. 서로 다른 커밋의 결과를 합쳐 최종 버전의 성공으로 기록하지 않습니다. 재현 중 코드 수정이 필요하면 새 커밋을 만들고 그 커밋으로 처음부터 확인합니다.

## 2. 원본 보존과 새 환경 준비 (실행 여부: 미확인)

**먼저 원본 저장소의 Git 최상위 폴더**에서 새 PowerShell을 엽니다. 이 단계에서 `git clean`, `reset --hard`, 기존 폴더 삭제, 강제 push를 사용하지 않습니다.

```powershell
Get-Location
git status --short
git branch --show-current
git rev-parse --show-toplevel
git rev-parse HEAD
git remote get-url origin
```

이 출력으로 **실제 원본 경로, 변경 중인 파일, 브랜치, 40자리 커밋, 원격 저장소**를 확인합니다. 현재 학생 PC에서 위 명령을 실행한 결과는 미확인입니다. 커밋 준비 중인 변경이 있으면 그 내용을 먼저 확인하고 보존합니다.

GitHub에 해당 커밋이 올라온 경우, **원래 프로젝트 바깥의 새로운 빈 상위 폴더**에서 다음과 같이 clone할 수 있습니다. 아래 `<새 작업 상위 폴더>`는 학생이 직접 정할 경로 자리표시자이며 그대로 실행하지 않습니다.

```powershell
Set-Location "<새 작업 상위 폴더>"
git clone https://github.com/JoYJ125/alekov.git keshev-reproduction
Set-Location .\keshev-reproduction
git fetch origin
git cat-file -t <확인한-40자리-커밋>
git switch --detach <확인한-40자리-커밋>
git rev-parse HEAD
git status --short
```

`git cat-file -t`가 `commit`을 출력하고 `git rev-parse HEAD`가 기록한 해시와 일치해야 합니다. **원격 저장소에 해당 커밋이 없다면** 원본 로컬 저장소를 대상으로 별도 폴더에 `git clone`하거나, 과제 화면의 수료 패키지 내보내기 절차를 따릅니다. 원본 로컬 경로와 도구 사용법을 확인하기 전에는 명령을 추측해 실행하지 않습니다. 기존 설정·인증·비밀 파일을 새 폴더에 무작정 복사하지 않습니다.

## 3. 새 환경 실행 절차 (아직 수행하지 않음)

새 clone의 `alekov/on-client` 폴더에서 PowerShell을 열고, [21단계 학생 실행 설명서](STUDENT_RUNBOOK.md)와 제공 [실행 안내](STUDENT_LAUNCH_GUIDE.md)를 따릅니다.

```powershell
Get-Location
Test-Path .\package.json
Test-Path .\tools\start-alekov.ps1
node --version
npm run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

- 소스상 기준 환경: Node.js 22~24 지원, 수업 기준 `24.19.0`; 사용자 PC의 설치 버전 **미확인**.
- `package.json`에 외부 npm 의존성은 선언되어 있지 않습니다. `npm install`을 필수로 가정하지 않습니다. `on-client/package-lock.json` 및 설치된 `node_modules` 상태는 현재 **미확인**입니다.
- 예상 서버 메시지: `케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.` 및 `서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.` — **실제 관측 아님**.
- 예상 브라우저 주소: `http://127.0.0.1:5189/`. `보호 현황` 화면의 렌더링·연동 상태는 **미확인**.
- 종료: 실행한 PowerShell에서 `Ctrl+C`; 재실행: 동일 새 폴더에서 같은 실행 명령. 종료·재실행 후 상태의 일치 여부 **미확인**.
- `npm run demo`는 예제 자료이며 실제 계정·접근 판정·XDR·AI·OSV 연결을 증명하지 않습니다. 유료 AI 요청이나 실제 보안 조치는 임의 실행하지 않습니다.

## 5. 데이터 보존·백업·복원 계획

| 대상 | 보존·백업 방법 | 복원·제한 |
|---|---|---|
| 학생 작성 코드·설명서 | Git 커밋과 저장소 URL·40자리 해시로 버전 고정 | 별도 폴더에서 동일 커밋 checkout; 기존 폴더 덮어쓰기 금지 |
| 실행·재현 관측 | 확인 시각, 환경, 단계별 상태, 비밀을 제거한 명령 출력·화면 근거를 이 문서에 기록 | 다른 커밋의 결과를 혼합하지 않고 해당 커밋의 기록만 비교 |
| 계정·인증·SDP 개인 설정 | 운영자 지침에 따라 프로젝트·Git·제출물 밖에서 별도 관리 | 새 환경에 자동 복사·커밋 금지; 복원·재발급은 운영자 안내 필요 |
| 실제 접근·XDR 사건과 조치 | 원천 시스템이 보관하는 데이터로 취급; 학생 앱의 Git 백업과 별개 | 원천 데이터 복구 권한·보존 정책은 **미확인**. 학생 화면·Git으로 복구할 수 있다고 주장하지 않음 |
| 패키지·OSV 조회 결과 | 조회 시점의 정확한 버전·lock 해시·출처·확인 시각을 결과로 기록 | 패키지·허용 목록이 바뀌면 재조회; 조회 실패를 `none_found`로 바꾸지 않음 |

백업·복원 동작은 아직 실제로 시험하지 않았습니다. 데이터베이스 백업 파일이나 복원 명령은 확인되지 않아 만들어 적지 않습니다.

## 6. 버전 결정과 미해결 항목

**현재 버전 표시: `0.2.11 (검증 중)`**. `v1.0`은 19단계 실제 집행 연결과 동일 최종 커밋의 누적 재현·공식 완료 조건이 모두 확인될 때만 사용합니다. 22단계 원문 AI 검토·단계 통과 자체는 운영 인증이나 `v1.0` 자동 인증이 아닙니다.

**기다림(UNV):** 실제 SDP 로그인·XDR 원천, AI 계정·권한·모델 응답, 사건 AI 설명, 19단계 실제 집행·효과, 20단계 OSV 조회, 새 환경 전체 기능 재현, 공식 22단계 판정. 제공 서버의 소스 존재·문서 검토·모의 화면 표시를 실제 운영 연결 성공으로 표현하지 않습니다.

## 7. 제출 경계 (실행하지 않음)

21·22단계는 워크벤치 `포털 제출 준비`의 지원 범위(13~20단계) 밖입니다. 과제 화면에 저장소 URL과 **실제로 제출할 최종 40자리 커밋**을 직접 입력합니다. 비공개 저장소는 공개로 변경할 필요가 없습니다.

비공개 원문이 필요하면 과제 화면의 `비공개 저장소 원문 준비 방법` → `원문 전달 도구 받기`를 사용합니다. ZIP과 JSON 출력 폴더는 프로젝트 밖에 둡니다. Git 최상위 폴더에서 화면에 표시된 `student-source-cli.mjs` 명령을 **실제 경로와 제출 커밋**으로 수정해 실행합니다. 구체적 인수·경로는 화면 확인 전에는 추측하지 않습니다. `비공개 저장소 원문 묶음`에 생성 JSON을 선택하고 저장소·커밋·단계를 확인한 후에만 제출합니다. 원문 전달과 AI 검토 통과는 별개이며, 원문 전달만 실패한 경우 안내된 `원문만 다시 보내기`를 사용합니다. **이 문서 작성 과정에서는 제출·원문 전달을 수행하지 않았습니다.**

## 8. 첫 번째 직접 확인

**원래 작업 폴더를 보존했는지 먼저 확인합니다.** 원래 저장소 Git 최상위 폴더에서 새 PowerShell을 열고 아래 명령만 실행합니다.

```powershell
Get-Location
git status --short
git branch --show-current
git rev-parse HEAD
git remote get-url origin
```

출력으로 원본 경로·변경 사항·브랜치·커밋·원격을 확인한 뒤 별도 폴더를 준비합니다. **실행 결과는 아직 미확인**입니다.
